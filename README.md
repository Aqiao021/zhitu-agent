# 职途助手 · 高职生求职差距诊断 Agent

> 线上体验：[打开职途助手](https://aqiao021.github.io/zhitu-agent/) · [本机记录](https://aqiao021.github.io/zhitu-agent/stats.html)

## 免费网页版（GitHub Pages）

线上版本无需购买服务器，支持 14 个专业、35 个岗位画像的搜索筛选、逐条加权诊断、30 天计划、模拟面试和就业问答。点击右上角模型状态，选择服务商、填写模型名和自己的 API Key，再点「验证并连接」。默认使用 DeepSeek 的 `https://api.deepseek.com/v1` 与 `deepseek-chat`；模型调用由使用者的服务商计费。

- Key 仅在当前页面内存中使用，刷新或离开页面后清除，不写入浏览器存储。请求由浏览器直接发往设置中的 HTTPS 模型接口；服务商须允许跨域请求。
- 最近 20 次诊断可在「诊断记录」查看，同一岗位的复诊会展示分数和要求变化；重新诊断会保留已有计划与打勾进度，可按需重新生成计划。
- 诊断结果、计划、勾选进度和使用记录保存在本机浏览器，不汇总其他访客的数据。可在「本机记录」页导出 CSV 或原始记录；比赛报告请自行收集、汇总参与者导出的记录，不能把它当全站统计。
- 公共岗位库随仓库发布更新。投稿、管理员审核入库和全站统计需要下面的 Python 服务版；免费静态版收起这些入口，仍可直接粘贴真实招聘进行诊断。
- 静态站点不内置公共密钥，附有 `robots.txt` 和禁止收录元信息；这些规则不能保证阻止恶意爬虫。

推送 `main` 后，GitHub Actions 会运行 Python 和浏览器逻辑测试，打包允许公开的文件并部署到原网址。密钥、数据库和 `data/` 不会进入 Pages 产物。以下运行及服务器配置说明适用于 Python 服务版。

先按专业或岗位名在岗位库里找到目标岗位（也可以直接粘贴一条招聘信息），再贴上简历，职途助手会：

1. **找岗位**：岗位库收录 14 个热门高职专业、35 个典型岗位画像。每个岗位列出必需和加分要求、要会的软件、可考的证书，并附上来源（高职院校公开的 2025 级人才培养方案、2025—2026 年公开招聘信息）。
2. **差距诊断**：按岗位库里的要求逐条对照简历，标出「具备 / 部分具备 / 缺少」，每条都附上简历原文作为依据。
3. **30 天计划**：AI 为每项差距设计学习模块（要学会的软件和按顺序执行的小任务），程序按你每天能投入的时间（1～4 小时）排进 30 天日历：学习日、复盘日（第 7/14/21/28 天）、综合项目（第 26/27/29 天）和第 30 天的复诊与模拟面试。每天都能打勾，打印成 PDF。
4. **模拟面试**：面试官针对你的短板出 5 道题，并对空泛的回答追问；最后按五个维度打分，给出改进建议和回答示范。
5. **就业问答**：只根据资料库作答，每句话都标出处，资料库包括国家职业标准、新职业、政策、学校与学院的公开信息。

## 三个设计亮点（答辩可以讲）

| 亮点 | 做法 | 解决的问题 |
|---|---|---|
| 结论可溯源 | 程序逐字核验模型给出的“简历原文”；原文在简历里找不到，就把该条降级并提示 | 防止大模型编造依据 |
| 分数和排期由程序计算 | 匹配度 = 具备 1 分、部分具备 0.5 分、缺少 0 分，必需项权重 2、加分项权重 1；30 天日历由程序排期，保证每天不超时 | 结果稳定、可解释 |
| 岗位库有来源 | 每个岗位画像都附人才培养方案或招聘页链接；同学提交的真实招聘经隐私处理和管理员审核后入库，单独标注 | 诊断依据可追溯，岗位库越用越真实 |
| 隐私与诚信 | 发给模型前，自动隐藏手机号、身份证号、邮箱、QQ/微信号、住址；服务器不保存简历原文；提示词禁止编造经历 | 保护同学隐私，符合求职诚信 |

## 运行方法（Windows）

1. 安装 Python 3.10 或更新版本，安装时勾选 **Add python.exe to PATH**。不需要安装任何第三方库。
2. 双击 `start.bat`。第一次运行会自动生成 `config.json`，并打开浏览器。
3. 未填写 API Key 时为**演示模式**：用简单的关键词规则演示整个流程，页面右上角会显示“演示模式”。
4. 接入真实大模型：用记事本打开 `config.json`，填写以下几项，保存后重新运行 `start.bat`。
   - `provider`：`openai`（OpenAI 兼容接口，DeepSeek、通义千问、智谱、Kimi 等都属于这一类）或 `anthropic`
   - `base_url`：服务商提供的接口地址，例如 `https://api.deepseek.com`
   - `model`：模型名称
   - `api_key`：你的密钥

   接口地址和模型名称以服务商的官方文档为准。`config.json` 已写进 `.gitignore`，不会被上传到 GitHub。

## 让每个同学用自己的 API Key

- 网页右上角的状态标签（“演示模式”/“AI 已连接”）可以点开，选择服务商（DeepSeek、通义千问、智谱、Kimi、硅基流动、火山方舟、OpenAI、Claude），填写模型名和自己的 API Key，可先点“测试连接”。
- Key 默认只保存在当前浏览器标签页，勾选“记住”才保存在这台设备；每次请求随请求发到服务器，只用来调用所选服务商，服务器不保存、不记录。
- 站点自己没配置 Key 时，没填 Key 的同学看到的是演示模式。想关闭这个功能，设置 `ZHITU_ALLOW_USER_KEY=false`。
- 公网部署必须使用 HTTPS。

## 让同学用手机试用

- 电脑和同学的手机连接同一个 Wi-Fi，启动后命令行窗口会显示类似 `http://192.168.x.x:8000` 的地址，同学用手机浏览器打开即可。
- 第一次运行时如果 Windows 防火墙弹窗，点击“允许访问”。
- 校园网有时会阻止设备之间互相访问。可以改用手机热点，或者部署到云服务器（同样只需要 Python）。

## 部署到公网

见 [DEPLOY.md](DEPLOY.md)。支持三种方式：Docker、Linux 服务器加 systemd、云平台。服务已内置以下防护：每个 IP 的调用限流、并发上限、内容安全策略（CSP）和统计页口令。

## 试用统计（报告数据来源）

- 在本机打开 `http://127.0.0.1:8000/stats`，可以看到试用人数、各功能的使用次数、成功率、平均耗时，以及用户评分和文字反馈。
- 点击“导出 CSV”可以导出全部数据，用 Excel 打开即可。
- 只统计接入真实模型后的使用记录，演示模式不计入。统计数据中不含任何简历内容。
- 想在别的设备上看统计页：在 `config.json` 里设置 `admin_token`，然后访问 `/stats?token=你的口令`。

## 建议的试用方案（20～30 名同学）

1. 每位同学在岗位库里选一个目标岗位（或贴一条真实招聘），用自己的简历做一次诊断，再生成 30 天计划。
2. 当场打分：诊断准不准（1～5 星）、有没有用。
3. 一周后回访：30 天计划完成了几天、几项任务。
4. 汇总以下数据写进报告：
   - 平均准确度评分
   - 认为有用的比例
   - 计划完成率
   - 典型的反馈意见，以及你据此做了哪些修改

## 项目结构

```
server.py          网页服务（Python 标准库）
zhitu/agent.py     诊断、30 天排期、面试、问答、招聘整理的逻辑与结果核验
zhitu/jobs.py      岗位库：检索、详情、真实招聘的提交与入库
zhitu/prompts.py   提示词（全部要求输出结构化 JSON）
zhitu/kb.py        知识库检索（SQLite FTS5 + 中文二元组）
zhitu/privacy.py   个人信息脱敏
zhitu/llm.py       模型接口（OpenAI 兼容 / Anthropic，默认 120 秒超时）
zhitu/demo.py      演示模式的规则模型
zhitu/store.py     试用统计与反馈
kb/*.md            资料库，每个文件头部写明来源和链接
kb/jobs.json       岗位画像库（14 个专业、35 个岗位，均附来源）
web/               网页前端（首页、工作台、原理页、统计与岗位库管理页；无构建，纯 HTML/CSS/JS）
tests/             单元测试（双击 run_tests.bat 运行）
```

## 岗位库

- 岗位画像在 `kb/jobs.json`，结构：`majors`（专业名称、专业代码、职业面向、来源）和 `jobs`（岗位名、别名、对应专业、工作内容、要求、软件工具、证书、来源）。每条要求带 `level`（必需/加分）、`category` 和用于简历匹配提示的 `keywords`。
- **同学贡献真实招聘**：工作台“找岗位”页右上角点“贡献真实招聘”，提交时会自动隐藏手机号、邮箱等信息。
- **管理员审核**：打开统计页 `/stats`（公网部署时加 `?token=口令`），在“岗位库管理”里点“整理预览”，模型会把招聘原文整理成岗位画像，确认后入库；前台标注“真实招聘”，可随时下架。导入的岗位存在 `data/zhitu.db`，不会覆盖 `kb/jobs.json`。
- 岗位画像不代表某家公司的真实招聘；证书名称、评价机构和职业代码以官方最新发布为准。

## 扩充资料库

在 `kb/` 下新建一个 `.md` 文件。文件开头按下面的格式写明标题、来源、链接和日期，正文用 `## 小标题` 分段，重启后自动生效：

```
---
title: 文件标题
source: 发布单位
url: 原文链接
date: 2026-10
---
## 小标题
正文……
```

**只收录有明确来源的公开资料**，例如学校就业处的通知、专业人才培养方案的公开部分。

## 限制说明

- 诊断和评分的质量取决于所接入的模型，结果仅供参考。
- 演示模式只做关键词匹配，不代表真实效果。
- 资料库截至 2026 年 10 月，政策和学校信息请以官方最新发布为准。
