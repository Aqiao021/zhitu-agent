> 线上体验地址：待部署完成后填写。

## 网页版：自带密钥，无需购买服务器

GitHub Pages 版保留诊断、计划、面试和问答。每位使用者点击“连接模型”，填写自己的 API Key；默认接口为 `https://api.deepseek.com/v1`，模型为 `deepseek-chat`。通过一次简短调用验证后才显示“AI 已连接”。网页托管免费，模型调用由各自的服务商账户计费。

密钥仅在当前页面内存中使用，只发送给使用者指定的 HTTPS 模型接口，不写入仓库、localStorage、sessionStorage 或统计记录；刷新、离开或关闭页面后需要重新填写。不内置共享密钥，不通过公共跨域代理转发。其他服务商需支持 OpenAI 兼容接口和浏览器跨域访问。

诊断结果（含遮盖后的简历引用）、计划、进度及使用记录保存在当前浏览器。点“本机记录”可导出 CSV、备份原始记录或清除本机数据。**此版本不集中收集同学的试用数据，不能把本机记录当成全站比赛统计。** 清理浏览器数据、换设备后记录不会自动恢复；如需比赛汇总，请同学主动导出并交给你汇总。

发布步骤及本地预览见 [DEPLOY.md](DEPLOY.md#github-pages-自带密钥版)。下面的 Python 启动方式仍可独立使用。

把简历和一条招聘信息贴进来，职途助手会：

1. **差距诊断**：把岗位要求拆成 5～12 条，逐条标出「具备 / 部分具备 / 缺少」，每条都附上简历原文作为依据。
2. **补差计划**：生成 4 周计划，每个任务都有预计小时数和验收标准，并保证不超过你给出的每周时间。
3. **模拟面试**：面试官针对你的短板出 5 道题，并对空泛的回答追问；最后按五个维度打分，给出改进建议和回答示范。
4. **就业问答**：只根据资料库作答，每句话都标出处，资料库包括国家职业标准、新职业、政策、学校与学院的公开信息。

## 三个设计亮点（答辩可以讲）

| 亮点 | 做法 | 解决的问题 |
|---|---|---|
| 结论可溯源 | 程序逐字核验模型给出的“简历原文”；原文在简历里找不到，就把该条降级并提示 | 防止大模型编造依据 |
| 分数由程序计算 | 匹配度 = 具备 1 分、部分具备 0.5 分、缺少 0 分，取平均；不让模型直接“拍”一个分数 | 结果稳定、可解释 |
| 隐私与诚信 | 发给模型前，自动隐藏手机号、身份证号、邮箱、QQ/微信号、住址；服务器不保存简历原文；提示词禁止编造经历 | 保护同学隐私，符合求职诚信 |

## 运行方法（Windows）

1. 安装 Python 3.10 或更新版本，安装时勾选 **Add python.exe to PATH**。不需要安装任何第三方库。
2. 双击 `start.bat`。第一次运行会自动生成 `config.json`，并打开浏览器。
3. 未填写 API Key 时为**演示模式**：用简单的关键词规则演示整个流程，页面右上角会显示“演示模式”。
4. 接入真实大模型：用记事本打开 `config.json`，填写以下几项，保存后重新运行 `start.bat`。
   - `provider`：`openai`（OpenAI 兼容接口，DeepSeek、通义千问、智谱、Kimi 等都属于这一类）或 `anthropic`
   - `base_url`：服务商提供的接口地址，例如 `https://api.deepseek.com/v1`
   - `model`：模型名称
   - `api_key`：你的密钥

   接口地址和模型名称以服务商的官方文档为准。`config.json` 已写进 `.gitignore`，不会被上传到 GitHub。

## 让同学用手机试用

- 电脑和同学的手机连接同一个 Wi-Fi，启动后命令行窗口会显示类似 `http://192.168.x.x:8000` 的地址，同学用手机浏览器打开即可。
- 第一次运行时如果 Windows 防火墙弹窗，点击“允许访问”。
- 校园网有时会阻止设备之间互相访问。可以改用手机热点，或者部署到云服务器（同样只需要 Python）。

## 部署到公网

见 [DEPLOY.md](DEPLOY.md)。支持三种方式：Docker、Linux 服务器加 systemd、云平台。服务已内置每 IP 调用限流、持久化的全站调用配额、反馈限流、并发上限、内容安全策略（CSP）和统计页口令；应用访问日志不会记录口令查询参数。

## 试用统计（报告数据来源）

- 在本机打开 `http://127.0.0.1:8000/stats`，可以看到试用人数、各功能的使用次数、成功率、平均耗时，以及用户评分和文字反馈。
- 点击“导出 CSV”可以导出全部数据，用 Excel 打开即可。
- 只统计接入真实模型后的使用记录，演示模式不计入。统计数据中不含任何简历内容。
- 想在别的设备上看统计页：在 `config.json` 里设置 `admin_token`，然后访问 `/stats?token=你的口令`。

## 建议的试用方案（20～30 名同学）

1. 每位同学用自己的简历，再选一条真实招聘信息，做一次诊断。
2. 当场打分：诊断准不准（1～5 星）、有没有用。
3. 一周后回访：补差计划完成了几项。
4. 汇总以下数据写进报告：
   - 平均准确度评分
   - 认为有用的比例
   - 计划完成率
   - 典型的反馈意见，以及你据此做了哪些修改

## 项目结构

```
server.py          网页服务（Python 标准库）
zhitu/agent.py     诊断、计划、面试、问答的逻辑与结果核验
zhitu/prompts.py   提示词（全部要求输出结构化 JSON）
zhitu/kb.py        知识库检索（SQLite FTS5 + 中文二元组）
zhitu/privacy.py   个人信息脱敏
zhitu/llm.py       模型接口（OpenAI 兼容 / Anthropic，60 秒超时，最多重试 1 次）
zhitu/demo.py      演示模式的规则模型
zhitu/store.py     试用统计与反馈
kb/*.md            资料库，每个文件头部写明来源和链接
web/               网页前端（首页、工作台、原理页；无构建，纯 HTML/CSS/JS）
tests/             单元测试（双击 run_tests.bat 运行）
```

## 扩充资料库

在 `kb/` 下新建一个 `.md` 文件。文件开头按下面的格式写明标题、来源、链接和日期，正文用 `## 小标题` 分段，重启后自动生效：

```
---
title: 文件标题
source: 发布单位
url: 原文链接
date: 2026-10
---
## 小标题
正文……
```

**只收录有明确来源的公开资料**，例如学校就业处的通知、专业人才培养方案的公开部分。

## 限制说明

- 诊断和评分的质量取决于所接入的模型，结果仅供参考。
- 演示模式只做关键词匹配，不代表真实效果。
- 资料库截至 2026 年 10 月，政策和学校信息请以官方最新发布为准。
